# Terraform Plan Image Reporting

Changed infrastructure and service plans produce `terraform-plan-image-infrastructure`
and `terraform-plan-image-service` artifacts. Each contains a PNG and a sanitized
`report.json` bound to the head, base, validation run, and run attempt. Artifacts
are retained for seven days. Raw plan JSON is never published. Existing binary
`tfplan` artifacts remain available for non-PR deployment jobs.

The Terraform-owned `autogenerated-plan-comment.yml` wrapper invokes the trusted
shared reporter after PR validation completes. Main and manual non-PR builds do
not post comments. The reporter validates the current producer revision, head,
base, run, attempt, and artifacts before updating one bot-owned PR comment.
Successful no-change plans replace previous images with a no-change result;
failed plan jobs are reported without an image. Fork PRs are not published by
this privileged reporter.

Inline PNG upload tries `PLAN_IMAGE_TOKEN`, then the existing `RENOVATE_TOKEN`
and `TF_VAR_GITHUB_PAT` candidates. These must be user tokens accepted by GitHub's
native attachment uploader; provisioning a secret does not establish that it is
compatible. A dedicated least-privilege `PLAN_IMAGE_TOKEN` is preferred. Tokens
are passed only through the child process environment and are never logged or
written to disk. Attachment upload uses a temporary, uniquely marked user
comment, copies its asset URL into the managed bot comment, then removes the
temporary comment. Failure to remove it emits a warning. A deleted attachment
comment's asset URL must be verified in a live smoke test before rollout.

`GITHUB_TOKEN` publishes the managed comment. If no configured token supports
attachments, the comment provides an artifact download link instead. No token
permissions, merge policy, or production approval rules are changed by reporting.

## Validation And Rollout

1. Run `node --test tools/*.test.mjs` in this repository and
   `TEST_PONTO=true node --test tools/render-plan.test.mjs` for a real PNG.
2. Lint both shared workflows and the generator's reporter wrapper with
   `actionlint`. Run `node repos/tools/render-gdq-workflows.mjs --check` from
   the parent workspace after generating pilot wrappers.
3. Publish shared producer and reporter changes before generated wrappers.
   Install the wrapper on `repos` and the GDQ pilot, then rerun PR validation.
4. Confirm each changed root has a nonempty PNG artifact and a single managed
   comment. Repeat validation to verify the comment updates instead of
   duplicating. Verify uploaded images remain visible after temporary-comment
   cleanup and that attachment failure produces working artifact links.
5. Confirm no comments appear for main builds, and production `tfplan` artifacts
   and approval gates still work. Roll out the remaining generated wrappers
   through the owning Terraform deployment with normal production approval.
